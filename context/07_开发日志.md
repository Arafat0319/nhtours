### 防灾机制：防止 Git 覆盖导致未提交工作丢失

**背景**: 用户要求「退回到问题发生之前」时，助手执行了 `git checkout <commit> -- trip_booking.html`，用历史版本覆盖了工作区，导致多日未提交的 WeTravel 版报名页（弹窗、样式等）丢失，无法从 Git 恢复。

**决策**: 建立并写入上下文的防灾机制：

1. **新增 [10_防灾与备份机制.md](10_防灾与备份机制.md)**  
   - 记录事件经过与教训。  
   - 规定：禁止在未确认/未备份时用 `git checkout -- <文件>` / `git restore` 等覆盖工作区；用户说「回退」时须先澄清意图并提示风险、建议备份。  
   - 提供「执行从 Git 恢复单文件前」的自检清单。

2. **在 [01_架构与规范.md](01_架构与规范.md) 中增加「防灾规则」**  
   - 禁止在未确认或未备份的情况下用 Git 覆盖工作区文件；要求 AI 与开发者遵守，并引用 10_防灾与备份机制。

3. **在 [README](README.md) 中登记 10_防灾与备份机制**  
   - 便于 AI 与开发者优先看到并遵守。

**影响**: 后续所有参与改代码的 AI 助手应加载并遵守 context 中的 10_防灾与备份机制；用户侧建议重要改动后及时提交、大改前手动备份、善用编辑器本地历史。

### Trip Slug 空值导致 500 错误修复

**问题**: 生产环境访问 `/admin/trips` 和 `/admin/trips?filter=draft` 时出现 500 错误。

**原因分析**:
- 后台模板使用 `url_for('main.trip_detail', slug=trip.slug)`
- 当 `trip.slug` 为 `None` 或空字符串时，Flask 抛出 `BuildError`
- Trip 创建流程（尤其是 draft 初始化）没有保证 slug 一定生成
- 生产数据库存在 slug 缺失的历史数据

**解决方案**:
1. **模型层**: 添加 SQLAlchemy 事件钩子，`before_insert` 和 `before_update` 时自动生成 slug
2. **模板层**: 添加防御性检查 `{% if trip.slug %}`
3. **字段约束**: `slug` 字段改为 `nullable=False`

**新增代码**:

### 财务报表金额修复

**问题**: Reports 页面显示的 `amount_paid` 包含了 Stripe 手续费，导致金额不正确。

**原因分析**:
- `handle_checkout_completed` 使用 `amount_total`（含手续费）更新 `booking.amount_paid`
- 报表计算 `amount_expected` 时未扣除折扣金额

**解决方案**:
1. 修改 `handle_checkout_completed`: 从 metadata 获取 `base_amount`
2. 修改 `calculate_trip_stats`: 扣除 `discount_amount`
3. 执行数据修复脚本，更正历史数据

**影响文件**:
- `app/routes.py`
- `app/admin/routes.py`
- `app/payments.py`

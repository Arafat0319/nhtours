# 支付与后台金额数据流

## 1. 概念定义

| 名称 | 含义 | 存储位置 / 计算方式 |
|------|------|----------------------|
| **订单应付 (Expected Amount)** | 客户应付的订单金额（套餐+附加-折扣），不含卡手续费 | 后台按 `Booking` + `BookingPackage` + addons + discount 计算 |
| **客户实扣 (Total Charged)** | 客户实际被扣的金额（含卡手续费） | 单笔：`Payment.amount`（美元）；汇总：succeeded / partially_refunded / refunded 的 `Payment.amount` 之和 |
| **卡手续费 (Card Fee)** | 单笔/总卡手续费 | 单笔：`Payment.fee_cents`（分）；汇总：同上状态各笔 `fee_cents/100` 之和 |
| **实收 (Net Received)** | 我们实际收到的金额（基础金额 − 已退基础部分） | 单笔：`base − refunded_amount`；汇总：各笔之和 |
| **已付金额 (Amount Paid)** | 订单上“已付”的基础金额（不含手续费），用于和 Expected 对比算 Pending | 存：`Booking.amount_paid`；展示：有支付记录时用 Payment 汇总的实收，否则用 `Booking.amount_paid` |
| **剩余可退** | 该笔 Payment 还能退多少（**基础口径，不含卡费**） | `payment_base_amount − payment.refunded_amount` |
| **默认可退上限** | 不含定金时的管理员可退上限 | `min(剩余可退, amount_paid − deposit_reserved)`；勾选 include_deposit 后 = 剩余可退 |

## 2. 支付成功时（Stripe 回调，见 `routes.py`）

- 创建/更新 **Payment**：
  - `amount` = 客户该笔实扣（美元，含手续费）
  - `fee_cents` = 该笔卡手续费（分）
  - `base_amount_cents` = 可选，基础金额（分）
  - `stripe_charge_id` = PaymentIntent `latest_charge`（便于 webhook）
  - `refunded_amount` = 已退**基础**金额（美元）；卡费永不计入
- 更新 **Booking**：
  - `amount_paid` += 本笔基础金额（美元，不含手续费）= `amount - fee_cents/100`

因此：**Booking.amount_paid** = 各笔支付的基础金额之和，应与 Payment 表汇总的「实收」一致（无退款时）。

## 3. 后台 Manage Booking API（见 `admin/routes.py`）

- **expected_amount**：按套餐+附加-折扣计算，与 Payment 无关。
- **payment_summary**（从 Payment 表汇总）：
  - `total_charged` / `card_fee` / `net_received`（含部分/全额已退笔，net 已扣退款）
- **payments[]**：含 `refunded_amount`、`refundable_remaining`（基础）、`max_refund_without_deposit`、`fee_amount`、`can_refund`、`base_amount`
- **amount_paid_display**：若有支付记录则 = `payment_summary.net_received`，否则 = `Booking.amount_paid`
- **pending_amount** = `expected_amount - amount_paid_display`
- **deposit_hint** / **deposit_reserved**：定金参考与默认保留额

## 4. 后台前端（Manage Booking 弹窗）

- **Order Summary**：展示 Trip Total (Expected)、若有支付则再展示 Total Charged、Card Fee、Net Received。
- **Payment Information**：Expected Amount、**Amount Paid**（输入框取 `amount_paid_display`）、Pending Amount（用 `amount_paid_display` 计算）。
- **保存**：提交的 `amount_paid` 写回 `Booking.amount_paid`，用于人工修正或与 Payment 汇总一致。
- **退款**（管理员决定）：
  1. 选择要退的 **Payment**
  2. **手续费不退**；Full remaining = 基础可退上限
  3. **Also refund deposit** 默认不勾选
  4. 全额剩余 / 部分金额
  5. **Reason 必填**
  6. 可选 Cancel booking / Manual only
  7. **$0 订单**：无 Payment 时可 amount=0 + Cancel booking 仅取消

## 5. 退款写入路径

- **Admin** `POST .../refund`：按基础金额 `process_refund(pi_…)` → `apply_refund_to_ledger`；Stripe 失败默认不落账；`include_deposit` 控制定金上限
- **Webhook** `charge.refunded`：Stripe 实扣累计经 `stripe_refunded_as_base` 截断到 base；本地落后则补基础差额

## 6. 注意点

- `Payment.amount` 为**实扣美元**；`refunded_amount` 为**已退基础美元**；`fee_cents` / `base_amount_cents` 为**分**。
- 老数据可能缺少 `fee_cents`：用 `base_amount_cents` 反推 `fee = amount - base`，都没有则手续费按 0 处理。
- 退款对 `Booking.amount_paid` 的扣减与退款金额 1:1（均为基础口径）；卡费部分即使在 Dashboard 退掉也不扣 Booking。

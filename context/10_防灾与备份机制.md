# 防灾与备份机制

> **⚠️ AI 助手必读**  
> 在执行任何**会覆盖工作区**的 Git 命令（如 `git checkout <commit> -- <文件>`、`git restore --source=<commit> <文件>`）之前，**必须先**阅读本文档并完成「操作清单」（第 3 节）。任一项未满足时，不得执行覆盖性恢复命令。

本文档记录「防止未提交工作丢失」的规则与流程，供开发者和 AI 助手共同遵守。**所有参与修改代码的 AI 助手必须阅读并遵守本章内容。**

---

## 1. 背景：曾发生的工作丢失事件

- **时间**: 2026-02-09 前后  
- **经过**: 用户反馈报名弹窗在窄屏下错位/消失，要求「退回到问题发生之前」。助手执行了 `git checkout <commit> -- flask-app/app/templates/booking/trip_booking.html`，用**仓库中某一历史提交**覆盖了**当前工作区文件**。  
- **后果**: 用户本地未提交的 WeTravel 版报名页（含多日实现的弹窗、样式、步骤条等）被旧版（无弹窗、继承 base.html）覆盖，**几天工作无法从 Git 恢复**。  
- **教训**: 用 `git checkout -- <path>` 或 `git restore <path>` 从历史恢复单个文件时，会**直接覆盖工作区**，未提交的修改会永久丢失。必须先确认无未提交修改，或先备份再操作。

---

## 2. 核心规则（AI 助手必须遵守）

### 2.1 禁止在未确认/未备份时用 Git 覆盖工作区文件

- **禁止**在用户存在未提交修改的情况下，直接执行以下或等效命令来「恢复」或「回退」某个文件：
  - `git checkout <commit> -- <文件或路径>`
  - `git restore --source=<commit> <文件或路径>`
  - 任何会**用版本库内容覆盖工作区**且导致未提交修改丢失的操作。
- **必须先**：
  1. 提示用户：该操作会覆盖当前工作区中的该文件，**未提交的修改将丢失**；
  2. 询问用户是否已备份或已提交，或建议用户先备份/提交再执行；
  3. 若用户坚持「回退」且未明确表示已备份，则**先建议**备份当前文件（例如复制到 `.bak` 或另一文件名），再执行回退。

### 2.2 用户说「回退」「恢复到之前」时的处理流程

1. **澄清用户意图**  
   - 「恢复到之前」可能指：  
     - (A) 撤销**当前未提交的编辑**（相当于丢弃工作区修改）；  
     - (B) 将文件**从版本库某一提交恢复**（会覆盖工作区）。  
   - 若用户未明确，应主动说明两种含义及风险，并询问是哪一种。

2. **若为 (B) 从版本库恢复**  
   - 先检查是否有未提交修改：可建议用户运行 `git status` 或由助手说明「若该文件有未提交修改，会被覆盖」。  
   - **强烈建议**：先让用户备份该文件（或助手提供复制到 `.bak` 的命令），再执行 `git checkout` / `git restore`。  
   - 不要代替用户假设「可以覆盖」，尤其当对话中曾有过多轮对该文件的实现细节时。

3. **若为 (A) 撤销未提交编辑**  
   - 可用 `git checkout -- <文件>` 或 `git restore <文件>`，但**仍应提示**：该操作会丢弃该文件上所有未提交修改，且无法用 Git 恢复。  
   - 若项目或编辑器有「本地历史」（如 Cursor Local History），可提醒用户可从那里找回。

### 2.3 建议用户侧的习惯（可写入 README 或开发规范）

- **重要功能或大改后及时提交**：避免仅存在于工作区的「唯一副本」因误操作丢失。  
- **大改前手动备份**：对关键文件（如 `trip_booking.html`）复制一份到 `.bak` 或带日期的副本，再执行可能覆盖的 Git 操作。  
- **善用编辑器本地历史**：如 Cursor 的 Local History，可在未提交情况下找回之前的版本。

## 3. 操作清单（执行「从 Git 恢复单文件」前必查）

在执行任何「用版本库内容覆盖工作区文件」的命令之前，助手应自检：

| 检查项 | 是/否 |
|--------|--------|
| 已向用户说明「该操作会覆盖工作区，未提交修改会丢失」 | ☐ |
| 已确认用户已备份或已提交，或已建议用户先备份再执行 | ☐ |
| 若用户未明确表示已备份，已提供备份建议（如复制为 `.bak`）并得到用户确认或明确要求继续 | ☐ |

**任一项为否时，不应执行覆盖性恢复命令。**

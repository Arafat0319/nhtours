## 环境准备

### 系统要求

| 组件 | 最低版本 |
|------|----------|
| Python | 3.9+ |
| Node.js | 16+ (构建 Tailwind) |
| Nginx | 1.18+ |
| MySQL | 8.0+ (生产环境) |

### 依赖安装

```bash
# 克隆项目
git clone <repo-url>
cd nhtours-website

# 创建虚拟环境
python -m venv venv
source venv/bin/activate  # Linux/Mac
# 或
.\venv\Scripts\activate   # Windows

# 安装依赖
pip install -r requirements.txt

# 安装前端依赖（如果需要构建 CSS）
npm install
npm run build:css
```

## 部署方式

### 方式一：传统服务器部署

#### 1. 配置环境变量

```bash
# 创建 .env 文件
cp .env.example .env

# 编辑配置
nano .env
```

#### 2. 数据库迁移

```bash
cd flask-app
flask db upgrade
```

> **2026-06-24**：首页 Testimonials 依赖 `testimonials` 表；GitHub Actions Deploy 在重启前执行 `flask db upgrade`。
>
> **Deploy 脚本要点**（`.github/workflows/deploy.yml`）：
> - 目录 `/var/www/nhtours`；venv 路径 `$DEPLOY_ROOT/venv`（无则自动创建）
> - 一律 `$VENV/bin/python -m pip` / `-m flask db upgrade`（勿依赖系统 `flask` 或 `~/.local`）
> - `source .env` 后再迁移；依赖含 `PyMySQL`、`cryptography`

#### 3. 启动应用

**开发环境**:
```bash
python run.py
```

**生产环境（使用 Gunicorn）**:
```bash
gunicorn -w 4 -b 0.0.0.0:8000 "app:create_app()"
```

#### 4. 配置 Systemd 服务

```ini
# /etc/systemd/system/nhtours.service
[Unit]
Description=NH Tours Flask Application
After=network.target

[Service]
User=www-data
Group=www-data
WorkingDirectory=/var/www/nhtours/flask-app
Environment="PATH=/var/www/nhtours/venv/bin"
EnvironmentFile=/var/www/nhtours/.env
ExecStart=/var/www/nhtours/venv/bin/gunicorn -w 4 -b 127.0.0.1:8000 "app:create_app()"
Restart=always

[Install]
WantedBy=multi-user.target
```

```bash
# 启用服务
sudo systemctl daemon-reload
sudo systemctl enable nhtours
sudo systemctl start nhtours
```

### GitHub Actions 自动部署（仅部署，无 CI）

本地自测通过后，推送到 `main` 分支即可自动部署到已有服务器（不跑 CI 测试）。

1. **仓库**：代码已在 GitHub（如 `Arafat0319/nhtours`），并已配置好服务器（方式一：克隆在 `/var/www/nhtours`、systemd 服务名 `nhtours`）。
2. **Workflow**：根目录 `.github/workflows/deploy.yml`，触发条件为 `push` → `main`；SSH 执行 `git reset --hard`、`venv` 装依赖、`source .env`、`flask db upgrade`、重启 `nhtours`。
3. **GitHub Secrets**（Settings → Secrets and variables → Actions）需配置：
   | Secret | 说明 |
   |--------|------|
   | `DEPLOY_HOST` | 服务器 IP 或域名 |
   | `DEPLOY_USER` | SSH 登录用户（如 `ubuntu`） |
   | `DEPLOY_SSH_KEY` | 部署用 SSH 私钥全文（服务器上需已加入对应用户的 `authorized_keys`） |
4. **部署目录**：workflow 中默认为 `/var/www/nhtours`；若不同，请编辑 `.github/workflows/deploy.yml` 中 `cd` 后的路径。
5. **首次**：在服务器上已克隆本仓库并配好 venv、systemd 后，之后只需 `git push origin main`，Actions 会自动完成拉取与重启。

#### 如何查看 Deploy 是否成功

1. 打开仓库 **Actions** 页：`https://github.com/Arafat0319/nhtours/actions`
2. 左侧点 **Deploy** workflow
3. 查看最新一次运行：绿色 ✓ = 成功，红色 ✗ = 失败
4. 点进运行 → **Deploy via SSH** 可查看服务器执行日志

#### 日常发布（每次改代码后）

> **流程约定**：先在本地完成测试（CI 在本地，非 GitHub Actions）。测试通过并**确认可以上线**后，再 push；AI 助手默认**不会**未经确认自动 push。

```bash
# 1. 本地自测（必做）
cd flask-app
python run.py          # 默认 http://localhost:8080
# 按改动逐项验证；有 DB 迁移时先 flask db upgrade

# 2. 确认无误后再提交并推送
git status          # 确认代码 + context/ 均已修改并 staged
git add ...
git commit -m "..."
git push origin main
# 然后到 Actions 页确认 Deploy 成功
```

**Context 同步**：push 前按 [11_推送与上下文同步.md](11_推送与上下文同步.md) 更新文档（至少 `07_开发日志.md`），与代码一并 commit。

**生产服务器示例**：`http://54.69.40.218`（Lightsail）；部署目录默认 `/var/www/nhtours`。

#### 部署后页面未变化的常见原因

| 原因 | 处理 |
|------|------|
| 改动未 commit / push | `git status` 检查；静态图片常见遗漏 |
| Actions Deploy 失败 | Actions 页查看日志；常见：`flask: command not found`（需 venv + `python -m flask`）、缺 `pymysql`、未 `source .env` |
| 浏览器或 Nginx 缓存 | Ctrl+F5；`/static/` 配置了 `expires 30d` |
| 只改了本地未 push 的实验页 | 确认 push 的 commit 含目标文件 |

**案例（2026-06-14）**：`/asia/family` Photo 1 本地有图、线上无图——因图片文件未进 Git；见 `07_开发日志.md` 对应条目。

### 方式二：Docker 部署

#### Dockerfile

```dockerfile
FROM python:3.11-slim

WORKDIR /app

COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

COPY flask-app/ ./flask-app/
COPY .env .

WORKDIR /app/flask-app

EXPOSE 8000

CMD ["gunicorn", "-w", "4", "-b", "0.0.0.0:8000", "app:create_app()"]
```

#### docker-compose.yml

```yaml
version: '3.8'

services:
  web:
    build: .
    ports:
      - "8000:8000"
    environment:
      - DATABASE_URL=mysql+pymysql://user:pass@db:3306/nhtours
      - SECRET_KEY=${SECRET_KEY}
    depends_on:
      - db

  db:
    image: mysql:8.0
    volumes:
      - mysql_data:/var/lib/mysql
    environment:
      - MYSQL_ROOT_PASSWORD=rootpass
      - MYSQL_USER=user
      - MYSQL_PASSWORD=pass
      - MYSQL_DATABASE=nhtours

  nginx:
    image: nginx:latest
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./nginx.conf:/etc/nginx/nginx.conf
      - ./ssl:/etc/nginx/ssl
    depends_on:
      - web

volumes:
  mysql_data:
```

## Nginx 配置

### 基础配置

```nginx
# /etc/nginx/sites-available/nhtours
server {
    listen 80;
    server_name nhtours.com www.nhtours.com;
    
    # HTTP 重定向到 HTTPS
    return 301 https://$server_name$request_uri;
}

server {
    listen 443 ssl http2;
    server_name nhtours.com www.nhtours.com;

    # SSL 证书
    ssl_certificate /etc/letsencrypt/live/nhtours.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/nhtours.com/privkey.pem;
    
    # SSL 优化
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers ECDHE-ECDSA-AES128-GCM-SHA256:ECDHE-RSA-AES128-GCM-SHA256;
    ssl_prefer_server_ciphers off;

    # 静态文件
    location /static/ {
        alias /var/www/nhtours/flask-app/app/static/;
        expires 30d;
        add_header Cache-Control "public, immutable";
    }

    # 上传文件
    location /uploads/ {
        alias /var/www/nhtours/flask-app/app/uploads/;
        expires 7d;
    }

    # 反向代理到 Flask
    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        
        # WebSocket 支持（如果需要）
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
    }

    # Gzip 压缩
    gzip on;
    gzip_types text/plain text/css application/json application/javascript text/xml;
    gzip_min_length 1000;
}
```

### 启用站点

```bash
sudo ln -s /etc/nginx/sites-available/nhtours /etc/nginx/sites-enabled/
sudo nginx -t
sudo systemctl reload nginx
```

### SSL 证书（Let's Encrypt）

```bash
# 安装 Certbot
sudo apt install certbot python3-certbot-nginx

# 获取证书
sudo certbot --nginx -d nhtours.com -d www.nhtours.com

# 自动续期
sudo certbot renew --dry-run
```

## Excel 导出刷新功能

导出的 Excel 内置 Web 连接，客户打开或手动刷新即可获取最新 Participants 数据。云端部署时需注意以下事项。

### 部署要求

| 项目 | 说明 |
|------|------|
| **导出位置** | 必须在**线上环境**导出 Excel（如 `https://yoursite.com`）。本地 localhost 导出时 URL 会指向 localhost，他人无法刷新。 |
| **反向代理** | 使用 Nginx 等代理时，必须正确传递 `Host` 和 `X-Forwarded-Proto`，否则生成的 URL 可能错误。 |
| **公网可达** | 客户电脑需能访问你的域名，Excel 才能向服务器发起刷新请求。 |

### Nginx 配置（必含）

```nginx
# 反向代理到 Flask 时必须包含以下 header
proxy_set_header Host $host;
proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
proxy_set_header X-Forwarded-Proto $scheme;   # 关键：让 Flask 知道是 https
```

### 可选 Flask 配置

若代理配置有误，可在 `config.py` 中显式指定：

```python
# 仅在代理 header 缺失时使用
app.config['PREFERRED_URL_SCHEME'] = 'https'
```

### 部署后自测步骤

1. 登录线上后台 → 行程管理 → 某行程 → **Download Excel** 导出
2. 用 Excel 打开下载的 xlsx 文件
3. 观察打开时是否自动刷新，或右键数据区域 → **刷新**
4. 若刷新失败，在浏览器中访问：  
   `https://yoursite.com/admin/trips/bookings/export/csv?token=xxx&format=html`  
   （token 可在导出时从网络请求中查看）
   - 能返回 HTML 表格：Excel 或网络问题
   - 返回 403/404：域名或代理配置问题

### 常见问题

- **打开不刷新**：检查客户网络是否能访问你的域名；Excel 需联网
- **URL 指向错误**：检查 Nginx 是否配置 `X-Forwarded-Proto`、`Host`

## 故障排查

### 常见问题

#### 1. MySQL 认证错误：cryptography package is required

**现象**: 连接 MySQL 时出现 `RuntimeError: 'cryptography' package is required for sha256_password or caching_sha2_password auth methods`。

**原因**: MySQL 8 默认使用 `caching_sha2_password`，PyMySQL 需要 `cryptography` 进行加密认证。

**解决**: `pip install cryptography`

#### 2. 应用无法启动

```bash
# 检查日志
sudo journalctl -u nhtours -f

# 检查端口占用
sudo netstat -tlnp | grep 8000
```

#### 3. 静态文件 404

```bash
# 检查文件权限
ls -la /var/www/nhtours/flask-app/app/static/

# 检查 Nginx 配置
sudo nginx -t
```

#### 4. 数据库连接失败

```bash
# 测试连接
mysql -h localhost -u nhtours -p nhtours

# 检查 MySQL 状态
sudo systemctl status mysql
```

#### 5. Stripe Webhook 失败

```bash
# 检查签名
# 确保 STRIPE_WEBHOOK_SECRET 正确

# 本地测试
stripe listen --forward-to localhost:5000/webhook/stripe
```

### 日志位置

| 服务 | 日志路径 |
|------|----------|
| Flask | `journalctl -u nhtours` |
| Nginx | `/var/log/nginx/error.log` |
| MySQL | `/var/log/mysql/error.log` |

### 性能优化

1. **Gunicorn Workers**: 设置为 CPU 核心数 × 2 + 1
2. **静态文件缓存**: Nginx 设置 `expires 30d`
3. **数据库连接池**: SQLAlchemy 配置 `pool_size`
4. **Gzip 压缩**: Nginx 启用 gzip

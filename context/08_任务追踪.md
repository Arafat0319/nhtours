### 📋 数据库迁移（方案 B）— 与用户分步实施

> **提醒**：开始创建托管库、改 `DATABASE_URL` 或停 VM 本机 MySQL 之前，先读本节。Stripe **Live** 仍延后；迁移可在沙盒收款测试期间或之后进行。

**目标架构**

```
用户 → https://nhtours.com → Lightsail VM（Nginx + Gunicorn）
                                    ↓ DATABASE_URL
                          Lightsail 托管 MySQL（主库 + AWS 自动备份）
```

**现网 → 目标**

| 项 | 现网 | 迁移后 |
|----|------|--------|
| MySQL | VM 本机 `localhost` | Lightsail **托管 MySQL** |
| 开发 | 本机 SQLite 或 MySQL | 建议本机 **MySQL 8**（`nhtours_dev`）；支付/分期用 MySQL 测 |
| 数据安全 | 依赖 VM 磁盘 | AWS 自动备份 + 应用与数据分离 |

**实施清单（按顺序，与用户协作）**

1. [ ] Lightsail 控制台 → **Databases** → 创建 MySQL 8（与网站 VM **同区域**）
2. [ ] 记录 endpoint、端口、主用户名/密码；配置 **仅允许网站 VM** 连接（托管库访问控制）
3. [ ] VM 上 **维护窗口**：`mysqldump` 现网库 → 导入托管库（或 Lightsail 快照/导入工具）
4. [ ] 修改 **`/var/www/nhtours/flask-app/.env`** 的 `DATABASE_URL` 为托管库连接串
5. [ ] `flask db upgrade`（确认 schema 一致）→ `sudo systemctl restart nhtours`
6. [ ] **冒烟**：后台登录、行程列表、Test 支付创建订单、Webhook、报表
7. [ ] 确认无误后：VM 上 **停用** `mysql` 服务（可选卸载）；保留一份最终 dump 到 S3 作归档
8. [ ] 文档更新 `06` / `07` 记录 endpoint 与完成日期（**勿把密码写入 Git**）

**开发环境说明（与 B 不冲突）**

- 生产 VM **不需要** MySQL；开发机 **可以且建议** 本机 MySQL 或 Docker MySQL
- 示例：`DATABASE_URL=mysql+pymysql://user:pass@127.0.0.1:3306/nhtours`（本地；可整库复制生产，见 `AI_快速参考` / `07` 2026-07-26）
- 生产托管迁移完成后：本地仍可用本机库；生产用托管 endpoint

**未选方案（备忘）**

- ~~VM 主库 + AWS 从库实时复制~~：运维复杂，本项目不采用
- ~~仅 cron dump 到 S3~~：可作迁移后 **补充** 备份，不替代托管库

> **提醒**：开始配置 SES、发送测试邮件或验收「支付确认 / 分期提醒 / Contact / Feedback 通知」之前，请先读本节。今日域名接入 **未** 完成 SES，但改变了 DNS 托管方式，对邮件有直接影响。

**为何与今日工作相关**

| 今日变更 | 对邮件的影响 |
|----------|----------------|
| DNS 从 Route 53 迁到 **GoDaddy** | SES 域名验证、DKIM 的 CNAME 须在 **GoDaddy DNS** 添加（不能只在旧 AWS DNS 配） |
| 站点 HTTPS 上线 | 邮件内支付链接、Feedback 链接应使用 **`https://nhtours.com`**，勿再用 IP |
| Stripe 仅沙盒 | 支付确认邮件可在 Test 支付后测；**Live 收款与 Live Stripe 一并延后** |

**配置清单（按顺序）**

1. [ ] **AWS SES 控制台** → 验证身份 → 域名 `nhtours.com`（或邮箱 `noreply@nhtours.com`）
2. [ ] 将 SES 提供的 **DKIM CNAME**（通常 3 条）添加到 **GoDaddy DNS**（与 `@` A 记录共存，勿删网站记录）
3. [ ] 可选：SPF TXT（若 SES 控制台提示）→ GoDaddy
4. [ ] 申请 **移出 SES 沙箱**（否则只能发到已验证收件人）
5. [ ] 服务器 **`/var/www/nhtours/flask-app/.env`** 确认：
   - `AWS_REGION`（或 SES 所用区域，如 `us-east-1`）
   - `AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY`
   - `SENDER_EMAIL=noreply@nhtours.com`（须与 SES 已验证身份一致）
   - `RECIPIENT_EMAIL=info@nhtours.com`（Contact/Feedback 通知收件）
   - **`BASE_URL=https://nhtours.com`**（定时分期提醒邮件中的 `/pay-installment/...` 链接；`tasks.py` 依赖此项）
   - ~~可选：`EXCEL_REFRESH_BASE_URL=…`（旧 Excel 实时刷新）~~ **Bookings 导出已改为静态快照，不再依赖此项**
6. [ ] `sudo systemctl restart nhtours`
7. [ ] **冒烟测试**：
   - Contact 表单 → `info@nhtours.com` 是否收到
   - Test 支付 → 买家是否收到收据邮件
   - 后台手动「发送分期提醒」→ 链接是否为 `https://nhtours.com/pay-installment/...`
   - Post-trip Feedback 链接：`https://nhtours.com/feedback`

**代码/env 注意**

- 代码读 **`SENDER_EMAIL`**，不是 `MAIL_SENDER`（旧文档笔误）
- `config.py` 尚未声明 `BASE_URL` 字段；`tasks.py` 通过 `current_app.config.get('BASE_URL')` 读取，须在 `.env` 中设置且需确认 Flask 能加载（测试时打印链接 URL）
- APScheduler 定时任务日志偶有 `Working outside of application context`，可能影响自动提醒；手动后台发送可先验证

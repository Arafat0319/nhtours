## 1. 数据链路概览

```
前端 (Templates → JS → Hidden JSON)
    ↓
表单校验 (Flask-WTF Forms)
    ↓
路由处理 (admin/routes.py)
    ↓
数据库 (models.py + migrations)
```

- **HTML 模板**：输入控件、隐藏字段
- **JS 逻辑**：构造 JSON、校验、提交
- **Hidden JSON**：`packages_json`、`addons_json`、`questions_json` 等
- **Flask-WTF**：表单验证
- **admin/routes.py**：解析 `request.form` / JSON，写入数据库
- **models.py**：表结构、字段类型、关系

## 4. 改动前的协作原则

若改动触及面较广，而用户尚未给出非常具体确切的指令，AI 拿不定主意时应主动询问细节，避免擅自假设或过度发散实现。

---

## 5. 每项改动时的核查清单

进行表单或数据库改动时，按以下顺序检查：

1. **模型**：是否新增/修改字段？需要迁移脚本 (`flask db migrate` / `flask db upgrade`)
2. **表单**：`admin/forms.py` 是否要加字段或改 HiddenField 校验
3. **路由**：`routes.py` 中对应 step 的 GET（回填）与 POST（保存）逻辑
4. **模板**：HTML 控件 `name`、`id` 是否与后端字段一致
5. **前端 JS**：构造 JSON 的键名与结构是否与后端 `json.loads()` 期望一致
6. **向后兼容**：已有数据读取、默认值、空值处理
7. **外键与级联**：新增关联表时的 cascade 行为

---

## 6. 关键技术点

- **JSON 字段**：Packages / Addons / Questions 等通过 `form.xxx_json.data` 传递，后端用 `json.loads()` 解析，再逐条建/删/改
- **yesno_text 答案**：`custom_answers[question_id]` 或 `custom_info[field_id]` 存储为 `{ value: "yes"|"no", details: "..." }`
- **图片上传**：通过 `utils.save_image()`，路径存入数据库字符串字段
- **事务**：`db.session.add/delete/commit` 成对出现，出错时需 `rollback`
- **Flask-Migrate**：模型变更后需执行 `flask db migrate` 和 `flask db upgrade`

## 本地测试安全模块

在 push 生产前，可在本机逐项验证。

**启动方式（二选一，日志都在 `flask-app/instance/audit.log`）：**

```powershell
# 推荐
cd flask-app
python run.py

# 也可在仓库根目录（已修复路径，无需担心写错目录）
python .\flask-app\run.py
```

浏览器：http://localhost:8080/admin/login

### 0. 本地 `.env` 建议

```bash
SECURITY_AUDIT_LOG=instance/audit.log
SECURITY_ALERTS_ENABLED=false   # 本地建议 false，避免误发邮件；生产改为 true
SECURITY_ALERT_EMAIL=你的邮箱
```

改 `.env` 后需 **重启** `python run.py`。

### 1. 审计日志（`security_audit.py`）

| 操作 | 你怎么做 | 预期 |
|------|----------|------|
| 登录成功 | 用顶部凭据登录后台 | `instance/audit.log` 出现 `admin_login_success` |
| 登录失败 | 故意输错密码 1～2 次 | 出现 `admin_login_failure`（含 IP） |
| 登出 | 点 **Log Out** | 出现 `admin_logout` |

**查看日志（PowerShell，在 `flask-app` 目录）：**

```powershell
Get-Content instance\audit.log -Tail 20
Select-String admin_login_failure instance\audit.log
```

每条是一行 JSON，例如：`{"ts":"...","event":"admin_login_success","username":"nh_ops_947d43","ip":"127.0.0.1",...}`

### 2. 登录暴力破解防护

1. **先退出登录**（否则看不到登录页行为）。
2. 连续用 **错误密码** 尝试登录 **5 次以上**（10 分钟内）。
3. 再试应提示：**「登录尝试过多，请稍后再试。」**
4. 日志里应有 `admin_login_rate_limited` 和 `security_alert`。
5. 本地 `SECURITY_ALERTS_ENABLED=false` 时：**只写日志不发邮件**。

等 **约 15 分钟** 或 **重启 `run.py`** 后可再次尝试登录。

### 3. 轮换凭据（仅运维，无网页改密）

生产 **不提供** `/admin/account/password` 页面。改用户名或密码请用：

1. **GitHub Actions** → **Security Hardening**（`NEW_ADMIN_PASSWORD` Secret + `admin_username` 输入）
2. **Lightsail SSH** → `scripts/rotate_admin_credentials.py`（见 [首次部署 / 轮换凭据](#首次部署--轮换凭据)）

改完后更新 `安全手册-凭据.local.md` 与 GitHub Secret。

### 4. 安全告警（`security_alerts.py`）

- 与「登录暴力破解防护」联动。
- **本地**：`SECURITY_ALERTS_ENABLED=false` → 仅 `audit.log`。
- **生产 + SES 配好后**：`SECURITY_ALERTS_ENABLED=true`，会发到 `SECURITY_ALERT_EMAIL`。

### 5. Excel 导出 token（90 天）

后台导出参与者时链接带 `token`，默认 **90 天**有效；勿长期泄露链接。

### 6. 本地与生产的差异

| 项 | 本地 | 生产 |
|----|------|------|
| 审计文件 | `flask-app/instance/audit.log` | `/var/log/nhtours/audit.log` |
| HTTPS / Secure Cookie | 开发模式无 Secure Cookie | HTTPS + Secure Cookie |
| 告警邮件 | 建议关闭 | SES 就绪后开启 |
| fail2ban / Nginx | 无 | SSH 配置 |

**若曾从仓库根目录启动过**：旧日志可能在 **仓库根** 的 `instance\audit.log`（不是 `flask-app\instance\`）。修复后请 **重启 run.py**，新记录统一写入 `flask-app\instance\audit.log`。

## 审计日志：在 SSH 里怎么查

Lightsail → **Connect using SSH**：

```bash
# 准备（首次部署后执行一次）
sudo bash /var/www/nhtours/deploy/security/setup_audit_log.sh

# 最近 50 条安全事件
sudo tail -50 /var/log/nhtours/audit.log

# 登录成功
sudo grep admin_login_success /var/log/nhtours/audit.log | tail -20

# 登录失败（暴力破解排查）
sudo grep admin_login_failure /var/log/nhtours/audit.log | tail -30

# 实时跟踪
sudo tail -f /var/log/nhtours/audit.log
```

**事件类型**

| event | 含义 |
|-------|------|
| `admin_login_success` | 登录成功 |
| `admin_login_failure` | 密码错误 |
| `admin_login_rate_limited` | 同一 IP 失败过多被临时封锁 |
| `admin_logout` | 登出 |
| `security_alert` | 触发告警（含 SES 未发时） |
| `fail2ban_ban` | fail2ban 封禁 IP |

**其他日志**

```bash
sudo journalctl -u nhtours -n 100 --no-pager
sudo tail -50 /var/log/nginx/access.log | grep admin
sudo fail2ban-client status sshd
```

## 安全告警邮件

应用内 `send_security_alert`：**SES 未配置时只写 audit.log**；接入 AWS SES 后自动发到 `SECURITY_ALERT_EMAIL`（默认同 `RECIPIENT_EMAIL`）。

**`.env` 可选变量**（`/var/www/nhtours/flask-app/.env`）：

```bash
SECURITY_ALERTS_ENABLED=true
SECURITY_ALERT_EMAIL=info@nhtours.com
SECURITY_AUDIT_LOG=/var/log/nhtours/audit.log
```

**当前会告警的情况**

- 同一 IP 约 10 分钟内后台登录失败 ≥ 5 次  
- （可选）fail2ban 封禁时写入 audit  

接入 SES 步骤见 `context/08_任务追踪.md` →「邮件/SES 上线前必读」。

## 服务器加固清单

在 SSH 中逐项核对（详细命令见 `deploy/security/`）：

| 项 | 目标 |
|----|------|
| Lightsail 防火墙 | 仅 **22、80、443**；无 3306 |
| MySQL | `bind-address = 127.0.0.1` |
| SSH | 密钥登录；禁用密码登录（确认密钥可用后再关） |
| fail2ban | 保护 `sshd` |
| Nginx | 引入 `deploy/security/nginx-security-headers.conf`（HSTS 等） |
| Nginx | `/admin/login` 可选 `limit_req`（见 `nginx-admin-rate-limit.snippet`） |
| logrotate | 复制 `deploy/security/logrotate-nhtours-audit` → `/etc/logrotate.d/nhtours-audit` |

**Nginx 安全头示例**（在 HTTPS `server { }` 内 `include`）：

```nginx
include /var/www/nhtours/deploy/security/nginx-security-headers.conf;
```

修改后：`sudo nginx -t && sudo systemctl reload nginx`

## 首次部署 / 轮换凭据

代码部署到服务器后，**在 SSH 执行一次**（把用户名密码换成你的，勿写入 Git）：

```bash
cd /var/www/nhtours/flask-app
set -a && source .env && set +a
export FLASK_ENV=production
export NEW_ADMIN_USERNAME='你的用户名'
export NEW_ADMIN_PASSWORD='你的长密码'
export OLD_ADMIN_USERNAME='admin'
../venv/bin/python scripts/rotate_admin_credentials.py
sudo bash /var/www/nhtours/deploy/security/setup_audit_log.sh
sudo systemctl restart nhtours
```

浏览器用新凭据登录 https://nhtours.com/admin/login 验证。

## 日常巡检

建议 **每周**（或收款旺季 **每天**）：

1. `grep admin_login_failure` 是否有异常 IP  
2. `journalctl -u nhtours` 是否有大量 500  
3. Stripe Dashboard → Webhooks 是否 200  
4. 确认备份策略（MySQL dump → S3，见安全加固计划第 3 轮）  

---

## 遭到攻击时

1. **不要慌**：支付资金在 Stripe；先保全证据。  
2. 查 `audit.log` 与 nginx access，记录攻击 IP。  
3. `sudo fail2ban-client set sshd banip <IP>`（如尚未封禁）。  
4. 若怀疑后台已沦陷：**立即轮换凭据**（Security Hardening 或 `rotate_admin_credentials.py`），检查 Stripe 与订单异常。  
5. SES 可用后确认是否收到自动告警邮件。

## 连接 SSH

- **服务器**
    - `54.69.40.218`（Lightsail **StaticIp-1**，已附加实例 `NHtours`）· 用户 `ubuntu` · 目录 `/var/www/nhtours`
    - **勿删** 该静态 IP。闲置未附加的其它静态 IP（曾见 `52.43.165.50`）可删；详见 `context/06`「Lightsail 静态 IP」

- **日常**

    ```powershell

    ```

- **首次配置**
    - 私钥：`E:\nh\SSH\LightsailDefaultKey-us-west-2.pem`
    - 编辑 `C:\Users\Arafat\.ssh\config`：

        ```sshconfig
        Host nhtours
            HostName 54.69.40.218
            User ubuntu
            IdentityFile E:/nh/SSH/LightsailDefaultKey-us-west-2.pem
            IdentitiesOnly yes
        ```

    - 若报 **Bad permissions**（PowerShell 管理员）：

        ```powershell
        icacls "E:\nh\SSH\LightsailDefaultKey-us-west-2.pem" /inheritance:r
        icacls "E:\nh\SSH\LightsailDefaultKey-us-west-2.pem" /grant:r "$env:USERNAME`:R"
        ```

    - 验证：`ssh nhtours` 然后 `nh-audit -n 5`

- **备选** — [Lightsail](https://lightsail.aws.amazon.com/) → **Connect using SSH**

> **注意** — 私钥文件勿提交 Git；`IdentityFile` 路径用正斜杠 `/`。

## 查审计日志

- **查看**

    ```bash
    nh-audit              # 当前文件最近 30 条（今天）
    nh-audit -n 50
    nh-audit --all        # 含轮转归档 .1 / .2.gz …（历史）；也可写 nh-audit -a
    nh-audit --all -n 100
    nh-audit -a -n 50     # 同上（短选项）
    nh-audit -f           # 实时跟踪当前文件（Ctrl+C 退出）
    ```

    logrotate 会按天切分：`audit.log`（今天）→ `audit.log.1` → `audit.log.2.gz` …（约保留 90 天）。  
    当前文件为空时用 **`nh-audit --all`** 看历史。

- **别名**（`~/.bashrc`）

    ```bash
    alias audit='nh-audit'
    alias auditf='nh-audit -f'
    alias audita='nh-audit --all'
    ```

- **Permission denied 还会不会再发生？**

    **正常不会。** 原因是旧 logrotate 用了 `create 640 www-data:www-data`；已改为 `create 664 ubuntu:www-data`，生产 `/etc/logrotate.d/nhtours-audit` 与仓库一致。  
    若再次出现，按下面排障；Deploy 会跑 `setup_audit_log.sh` 重写正确配置。

- **排障：Permission denied / 日志写不进去**

    常见原因：**logrotate** 曾用 `create 640 www-data:www-data`，轮转后 `ubuntu`（Gunicorn / `nh-audit`）读不了。

    ```bash
    # 立刻恢复可读可写
    sudo chown ubuntu:www-data /var/log/nhtours /var/log/nhtours/audit.log
    sudo chmod 775 /var/log/nhtours && sudo chmod 664 /var/log/nhtours/audit.log

    # 重装权限 + 修正 logrotate（Deploy 也会跑；可手动）
    sudo bash /var/www/nhtours/deploy/security/setup_audit_log.sh

    # 确认
    ls -la /var/log/nhtours/audit.log
    # 期望：-rw-rw-r-- ubuntu www-data
    nh-audit -n 5
    ```

> **提示** — Deploy 工作流通常会自动执行 `setup_audit_log.sh`。事件含义见 [参考 → 审计事件](#审计事件)。

## 轮换凭据

- **方式 A — GitHub Actions**
    - Workflow：**Security Hardening**
    - Secret：`NEW_ADMIN_PASSWORD` · 输入：`admin_username`

- **方式 B — SSH**

    ```bash
    cd /var/www/nhtours/flask-app
    set -a && source .env && set +a
    export FLASK_ENV=production
    export NEW_ADMIN_USERNAME='你的用户名'
    export NEW_ADMIN_PASSWORD='你的长密码'
    export OLD_ADMIN_USERNAME='当前用户名'
    ../venv/bin/python scripts/rotate_admin_credentials.py
    sudo bash /var/www/nhtours/deploy/security/setup_audit_log.sh
    sudo systemctl restart nhtours
    ```

- **改完后**
    - 更新 `安全手册-凭据.local.md` 与 GitHub Secret
    - 浏览器验证 https://nhtours.com/admin/login

> **危险** — 生产**没有**网页改密页；勿在聊天或 Git 里粘贴明文密码。

## 加固与巡检

- **清单**（详细命令 → `deploy/security/`）
    - 防火墙：仅 22、80、443（**Lightsail 控制台**核对，见下节「Lightsail 网络防火墙」）
    - MySQL：`bind-address = 127.0.0.1`（✅ 2026-07-27 SSH 已确认；3306 不对外）
    - `SECURITY_ALERTS_ENABLED=true`（✅ 2026-07-27 生产已开）
    - SSH 密钥登录 · fail2ban · Nginx 安全头 · logrotate

- **Lightsail 网络防火墙**（✅ 2026-07-27 已核实：仅 **22 / 80 / 443**）
    - 复查路径：[Lightsail](https://lightsail.aws.amazon.com/) → 实例 → **Networking** → IPv4 Firewall
    - 若日后误加 MySQL/3306 等规则对 `Anywhere` 开放 → 删掉

> 说明：服务器上 `ufw` 可为 inactive；外网挡端口以 Lightsail 网络层为准。MySQL 另有 `bind-address=127.0.0.1`。

- **巡检**（每周；旺季每天）
    - `nh-audit` — 异常登录 IP
    - `journalctl -u nhtours` — 500 错误
    - Stripe Webhooks — 200
    - MySQL 备份

## 审计事件

| event | 含义 |
|-------|------|
| `admin_login_success` | 登录成功 |
| `admin_login_failure` | 密码错误 |
| `admin_login_rate_limited` | 同 IP 失败过多，临时封锁 |
| `admin_logout` | 登出 |
| `security_alert` | 触发告警（SES 未配时只写日志） |
| `fail2ban_ban` | fail2ban 封禁 IP |

```bash
sudo tail -50 /var/log/nhtours/audit.log
sudo grep admin_login_failure /var/log/nhtours/audit.log | tail -30
```


# 说明

> **Explanation** — 理解设计，不是操作步骤。

## 为什么用 UTC？

- 审计日志统一存 **UTC**（`Z` 结尾），避免夏令时和多时区混乱。
- `nh-audit` 表头为 **TIME (UTC)**，不会自动转本地时间。

| 时区 | 换算 | 例：`05:46:08Z` |
|------|------|-----------------|
| 美西 PDT | UTC − 7 | 前一天 22:46 |
| 中国 CST | UTC + 8 | 当天 13:46 |

行业惯例：**存储用 UTC，展示可按需加本地列**（见 `context/07` 讨论）。

# 开发自测

> **Tutorial** — push 前在本机走一遍（开发者用）。

```powershell
cd flask-app
python run.py
# http://localhost:8080/admin/login
```

`.env`：

```bash
SECURITY_AUDIT_LOG=instance/audit.log
SECURITY_ALERTS_ENABLED=false
```

| 测什么 | 操作 | 预期 |
|--------|------|------|
| 审计 | 登录 / 错密码 / 登出 | `success` / `failure` / `logout` |
| 限流 | 10 分钟内错密 ≥5 次 | 「登录尝试过多」 |
| 表格 | `python ../deploy/security/audit_tail.py instance/audit.log -n 15` | 列对齐 |

> **提示** — 限流后等约 15 分钟或重启 `run.py` 再登录。
